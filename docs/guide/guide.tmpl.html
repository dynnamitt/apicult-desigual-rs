1 · The math functions, simplest first

src/math.rs holds pure functions over glam and hexx types. None of them know about HGridLayout. They're ordered here from plain arithmetic to the grid combinatorics the rest of the crate is built on.

One convention to keep in mind: a hex's world position is a Vec2(x, z). Height is y, so 3D points are Vec3(x, height, z).

1.1 map_noise_to_rangelinear rescalenoise in [−1, 1] → any range

Noise generators return values centred on zero, roughly in [-1, 1]. This is the straight line through (-1, min) and (1, max):

out = min + (n + 1) / 2 · (max − min)

The layout calls it twice per cell. Once for height, into [0, max_height] (default 20). Once for the cell's corner radius, into [nominal · min_ratio, nominal · max_ratio] (default 0.2 to 3.6 for a nominal radius of 4). The radius is smaller than the spacing between hex centres, and that leftover space is the gap the rest of this page is about.

{{f1}}
1.2 edge_cuboid_transformvectors + one rotationmidpoint, length, rotation for a beam on an edge

This one gives you the placement for a box that should lie along an edge from from to to:

  • the midpoint, (from + to) / 2
  • the length, |to − from|
  • the rotation that turns the box's own +X axis onto the edge direction

Scale a unit cube by length on X, rotate, then translate.

{{f2}}
1.3 gap_vertex_datatranslate + cross productshift to origin, normal from a cross product

This prepares a gap polygon for mesh upload. It moves the polygon so its first vertex is at the origin, and finds which way it faces.

The face direction is the cross product of the first two edges out of v0. For these gaps the winding makes that cross product point down, so the function negates it.

When flat is set it ignores the slope and returns straight up, so tilted gaps get the same lighting as the flat hex tops.

{{f3}}
1.4 idw_interpolate_heightweighted averageheight at any point as a 1/d² weighted mean

This answers "how high is the ground at an arbitrary point Q?" Every nearby corner votes with its height, and its vote counts 1 / d², where d is its distance to Q in the x–z plane:

h(Q) = Σ hᵢ / dᵢ² ⁄ Σ 1 / dᵢ²

Near a corner its weight blows up, so the function simply snaps to that corner once d² < 0.001. It returns None for an empty list and leaves the fallback to the caller.

{{f4}}
1.5 quad_corner_indiceshex direction tableswhich corners form the gap across an edge

Here the hex lattice itself comes in. hexx numbers a hex's six corners (VertexDirection) and six edges (EdgeDirection) separately. Edge i runs from corner i to corner i+1.

The gap between a hex and its neighbour across edge e is a quad with two corners on each hex. On the neighbour, that same edge is edge e+3, and it is walked in the opposite direction. The function returns the four indices in a fixed order, (v0, v1, n0, n1), so the quad always comes out as [v0, n0, n1, v1].

edgefaces neighbourowner corners v0, v1neighbour corners n0, n1
0(+1, 0)0, 14, 3
2(−1, +1)2, 30, 5
4(0, −1)4, 52, 1

It is only defined for even edges, because of the ownership rule below.

{{f5}}
1.6 gap_fillerownership countingcounts gaps under the ownership rules

The two ownership rules that keep every gap from being drawn twice:

  • Quads. Every interior edge is shared by two hexes. If one meets it as an even edge (0, 2, 4), the other meets it as odd (3, 5, 1), because e+3 flips parity. So "the hex whose index is even owns it" picks exactly one owner.
  • Junction triangles. Every interior corner is shared by three hexes. hexx's GridVertex::coordinates() lists those three hexes in a canonical order, and the first one owns the triangle. In practice that means each hex owns the triangles at its corners 0 and 1.

A gap is only emitted when every hex it touches exists. gap_filler counts what these rules would produce for any set of cells. Its unit tests assert the count matches what gap_quads and gap_tris actually emit, so if the rules drift apart in one place the tests catch it.

2 · Resolution functions from hexx

Splitting a hex grid into hexagonal chunks rests on four functions from the upstream hexx crate (0.24), in hex/mod.rs. hexx calls them resolutions. A radius-r hexagon of cells is treated as one cell of a coarser hex grid. They're listed in order of complexity. The algorithm is Sander Evers' "hexagon tiling of a hexagonal grid".

They define what a chunk coordinate means: which cells a chunk holds, where its centre is, and where a cell sits inside it.

R.1 Hex::range_countcells in a radius-r hexagon

range_count(r) = 3·r·(r + 1) + 1

Ring k has 6k cells, and summing over rings plus the centre gives this. For r = 2 it's 19, for r = 6 it's 127, and for a radius-60 grid it's 10,981. In to_lower_res this number is called the area: one coarse cell holds exactly this many fine cells.

R.2 Hex::to_higher_reschunk coordinate → its centre cell, linear

Going down to finer cells is a plain linear map in cubic coordinates (x, y, z = −x − y):

to_higher_res((x, y), r) = ( x·(r+1) − r·z , y·(r+1) − r·x )

Chunk (1,0) goes to (2r+1, −r), which is (5,−2) for r = 2. Every chunk centre is an integer combination of two such basis vectors. The coarse lattice is the fine one scaled by √range_count(r) and rotated, so chunk rows never line up with cell rows.

The function is const and exact integer arithmetic.

{{f12}}
R.3 Hex::to_local and wrap_in_rangeoffset inside the chunk; a wraparound world

to_local(h, r) = h − to_higher_res(to_lower_res(h, r), r)

This gives a cell's position relative to its chunk's centre, and it's always within distance r. It's useful when storing chunks in two ways:

  • It's the same small set of values in every chunk, so a full chunk's 19 (or 127) cells can sit in fixed slots, ordered by local coordinate, no matter where the chunk is in the world.
  • Together with the chunk coordinate it fully recovers h, so cell records could store a local (i8, i8) instead of a world (i32, i32).

wrap_in_range(r) is literally to_local(r). Read as "fold the plane onto one hexagon around the origin", it gives a seamless wraparound map. That's an alternative to "infinite": a finite world without edges, where every chunk past the rim is a copy.

{{f13}}
R.4 Hex::to_lower_rescell → chunk coordinate, the hexmod

Going up to coarse cells has to answer "which hexagon contains me?" for a hexagonal tiling. A plain division can't do that. hexx does it in two floor steps over cubic coordinates, with area = range_count(r) and shift = 3r + 2:

X = ⌊(y + shift·x) / area⌋
Y = ⌊(z + shift·y) / area⌋
Z = ⌊(x + shift·z) / area⌋

chunk = ( ⌊(1 + X − Y) / 3⌋ , ⌊(1 + Y − Z) / 3⌋ )

Step 1 projects the cell onto three axes, each skewed by shift so it runs along the rotated coarse lattice, and counts how many area-wide bands it has crossed. That places the cell in one triangle of a triangular grid. Step 2 is ordinary hex rounding of that triangle onto the hexagon that owns it. Worked through for h = (4,0), r = 2 (area 19, shift 8):

stepvalue
cubic (x, y, z)(4, 0, −4)
X = ⌊(0 + 8·4) / 19⌋⌊32/19⌋ = 1
Y = ⌊(−4 + 8·0) / 19⌋⌊−4/19⌋ = −1
Z = ⌊(4 + 8·(−4)) / 19⌋⌊−28/19⌋ = −2
q = ⌊(1 + X − Y) / 3⌋⌊3/3⌋ = 1
r = ⌊(1 + Y − Z) / 3⌋⌊2/3⌋ = 0
chunk(1, 0) ✓ matches figure R.3

A limit for large coordinates: hexx computes y + shift·x in i32, then divides as f32. Integers are exact in f32 only up to 2²⁴ = 16,777,216. Past about 16.7M / (3r + 2) cells from the origin (roughly 840,000 cells for r = 6), the floor can land on the wrong side of a band edge, and a cell can be put in the wrong chunk. A grid that reaches that far needs an integer div_euclid version of this function.

3 · What one cell owns

HGridLayout::new builds a HexagonalMap of radius settings.radius around Hex::ZERO. Each cell gets its height and radius from Fbm<Perlin> sampled at its world centre divided by a scale (50 for height, 30 for radius).

  • A cell's values depend only on its world position and the seeds. Its neighbours don't affect them, and neither does the size of the grid.
  • Corners are centre + unit_corner · cell.radius, while centres sit on the fixed lattice spacing nominal_hex_radius. So a smaller cell widens the gaps around it, but never moves.

4 · Entangled cells

#8 added a per-cell entangled flag, set through the entangle: &[Hex] argument of HGridLayout::new, and two rules for the gaps:

  • A gap quad is entangled only if both its cells are. #8 calls this the bridging propagation rule.
  • Junction triangles are never entangled. all_tris(true) skips them, and all_tris(false) always includes them.

all_tris(entangled), hex_face_tris(entangled) and gap_quad_tris(entangled) return only the matching part, so a consumer can drive entangled and plain cells with two materials. entangle_borderline(dir) marks one outer side of the grid.

Entangling a grid's whole outer ring has a useful effect. all_tris(false) skips the ring's faces and the gaps between two ring cells, but keeps every gap that reaches an inner cell, whoever owns it. The inner cells come out with a closed outline:
